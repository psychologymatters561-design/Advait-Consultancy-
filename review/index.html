02

How a page comes alive

01

Document paints from inline critical CSS

The browser gets fully-formed HTML with the entire stylesheet in the <head>. First paint needs no round-trip — the strength of the no-build approach, and the root of its duplication.

02

Fonts resolve — two different ways

The main site self-hosts woff2 with font-display:swap. The dossier and desk instead pull fonts.googleapis.com — a render-blocking third-party request the rest of the site deliberately avoids.

03

Vendor scripts load deferred

gsap, ScrollTrigger and lenis are self-hosted and defer-ed, so nothing blocks parse. If they never arrive, the page still works — the base experience is real HTML.

04

The enhancement layer upgrades in place

On load, Lenis takes over scrolling, GSAP pins the four-principle carousel to scroll, and a WebGL shader plus a canvas dust field breathe behind the hero. Touch and reduced-motion fall back to native scroll-snap.

05

Interaction stays on the client

The corridor-notes form validates, writes to localStorage, and POSTs to a configured endpoint — or opens a mailto: draft when none is set. The “Advait Capital” portal swaps to a second, light-themed world held in the same document.

03

Where it strains

Ranked by what will hurt first as the site grows. The top finding is already fixed on this branch; the rest are sequenced into the roadmap that follows.

CriticalDuplication · Scalability

One design system, maintained in five places

The four corridor-note articles each carried a byte-for-byte identical 68-line stylesheet; the brand tokens and @font-face block were re-inlined on every dark page. Publishing a new note meant cloning an entire design system by hand and keeping five copies in sync forever — the single biggest scalability risk in the repo.

Proof · diff dwarka.css infra.css → empty · diff dwarka.css noida.css → empty · 68 × 4 = 272 identical lines
HighArchitecture · Consistency

Three divergent design systems, no shared token layer

The neomorphic site speaks --bg / --accent; the dossier speaks --ink / --amber / --gold; the desk invents --ink / --paper again. One brand, three vocabularies — a single colour or type change has to be made, and reconciled, in three unrelated places.

Fix · promote a shared token layer; the systems become themes over one source, not three forks
HighData · Correctness

The corridor data has no home

The desk’s SECTORS, POLICIES, INDUSTRIES and CONNECTIVITY are hardcoded as JS literals inside the HTML document, while the dossier restates overlapping facts about the same corridor independently. Two hand-maintained sources for one truth is a drift waiting to happen — the day a figure is updated in one and not the other.

Fix · lift the model into a JSON module both views read; render from data, never from markup
MediumPerformance

The hero runs three animation loops at once

A custom-cursor lerp, a canvas dust field, and a WebGL fragment shader computing three four-octave fbm noise samples per pixel, per frame all run alongside GSAP and Lenis — with no shared scheduler and no frame budget. It is gorgeous on a laptop and expensive on a low-end phone GPU.

Fix · one rAF scheduler, an FPS ceiling, and a visibility gate already present but not unified
MediumPerformance · Consistency

A second full page lives inside the landing DOM

“Advait Capital” (World 2) is a complete, light-themed page shipped hidden inside index.html, inflating the most performance-critical document on the site and its critical path — for content most visitors never open.

Fix · promote it to its own route; load it on intent, not on every landing
LowMaintainability

Readiness is decided three different ways

body.ready is set by a 1700 ms timer inside the main script, again by a trailing 1800 ms <script>, and again by the preloader — three code paths racing to do one thing. Harmless today; a trap the next time the timings are touched.

Fix · one readiness owner; keep a single documented fallback
04

The fix, shipped

The critical finding is resolved on this branch. The duplicated design system now lives in two shared stylesheets; every note links them instead of re-declaring them. The transformation is provably render-identical — the extracted CSS is verbatim, and the only token deltas are longer-but-equivalent font fallbacks and two unreferenced variables.

</style>

05

The refactoring strategy

Staged so the live site is never at risk. Each stage is independently shippable and behaviour-preserving; nothing here changes what a visitor sees.

1

Extract the shared design system

tokens.css + notes.css; every note links them. The duplication is gone and the notes design is edited in one file.

Shipped
2

Unify the three systems onto one token layer

Reconcile neomorphic, cockpit and desk onto shared primitives, then self-host the dossier & desk fonts to drop the Google Fonts round-trip.

Next
3

Give the data a home

Lift the desk model into a JSON module; render both the desk and the dossier from it so the corridor has one source of truth.

Next
4

Add a minimal build

A tiny partial/templating step lets the hero keep inline critical CSS without hand-copying tokens — and unlocks CSP + SRI on the vendor scripts.

Later
5

Budget the motion

One rAF scheduler for cursor, dust and shader; an FPS ceiling and a shared visibility gate, so the hero stays cinematic on low-end GPUs.

Later

A living design deserves a living system beneath it.

Stage 1 is on the branch, provably identical to production. index.html, the dossier and the desk were left byte-for-byte untouched — deliberately: the landing page keeps its inline critical CSS for first paint, and the two are separate tools. They are Stage 2+ work, not oversights.
